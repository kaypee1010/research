# PHASE 3 — DESTROY WEAK IDEAS

For every existing idea, actively search for reasons it should NOT be selected.

Use these tests:

### A. Novelty Test
Would a knowledgeable evaluator say:

> “This already exists.”

If yes, identify what exists and redesign the idea.

### B. “App Syndrome” Test
If the idea is essentially:

> “Create an app/platform/dashboard using AI...”

assume it is weak until proven otherwise.

The technology is NOT the innovation.

The innovation must be in the **system, mechanism, incentive, workflow, institutional model, data architecture, delivery model or measurable outcome**.

### C. Government Duplication Test
Identify relevant existing government schemes/platforms/programmes.

If the idea duplicates one, do not defend it.

Either:

- kill it,
- differentiate it substantially, or
- redesign it as an interoperability / intelligence / outcome layer.

### D. Scale Test
Can this realistically move from:

Pilot → District → Haryana → India

without becoming financially or institutionally impossible?

### E. Implementation Test
Who would actually implement it on Monday morning?

If the answer is vague, penalise it heavily.

### F. Adoption Test
Why would citizens, government officials, employers, schools, hospitals, farmers, MSMEs or other users actually adopt it?

### G. Impact Test
Can impact be expressed through measurable outcomes rather than vague claims such as:

“empowerment”, “awareness”, “efficiency”, “inclusion” or “digital transformation”?

### H. Defensibility Test
What prevents another team from proposing the same idea?

### I. 2047 Test
Would this still matter in 2047?

### J. SevaFirst Test
Does the innovation meaningfully improve public service delivery, citizen outcomes, institutional effectiveness or inclusive development?
